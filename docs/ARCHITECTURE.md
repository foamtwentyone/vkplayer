# Архитектура и протокол

## Компоненты

| Компонент | Процесс | Ответственность |
|---|---|---|
| `VkHotkeys.App` | `VkHotkeys.exe` (один экземпляр) | хук клавиатуры / RegisterHotKey, `PlayerController`, сервер канала, окно, трей, плашка, автозапуск, регистрация моста |
| `VkHotkeys.Core` | библиотека | протокол, кадрирование, комбинации, проверка конфликтов, сопоставление нажатий, настройки, контроллер |
| `VkHotkeys.Bridge` | `VkHotkeys.Bridge.exe` (по одному на браузер) | хост Native Messaging: stdin/stdout браузера ⇄ именованный канал приложения |
| `background.js` | service worker расширения | соединение `connectNative`, реестр вкладок VK, выбор вкладки, таймауты |
| `content.js` | изолированный мир вкладки | посредник `window.postMessage` ⇄ `chrome.runtime.Port` |
| `page.js` | основной мир страницы vk.com | поиск плеера и выполнение команд с проверкой результата |

## Транспорт

* Браузер ⇄ мост: Chrome Native Messaging — `uint32 LE длина + UTF-8 JSON`, максимум 1 МБ на сообщение к браузеру.
* Мост ⇄ приложение: именованный канал `\\.\pipe\VkHotkeys.Bridge.v1.<пользователь>`, **тот же формат кадров**
  (мост не разбирает сообщения, кроме поля `type` для кэширования). Канал создаётся с `PipeOptions.CurrentUserOnly`:
  подключиться может только процесс того же пользователя.
* Приложение — сервер канала с неограниченным числом экземпляров: каждый браузер = отдельное подключение.

## Сообщения

Расширение → приложение:

```jsonc
{ "type": "hello", "browser": "Chrome", "version": "1.0.0" }
{ "type": "state", "state": {
    "vkTabs": 1, "tabId": 123, "playerFound": true, "hasTrack": true, "playing": true,
    "title": "…", "artist": "…", "volume": 0.65, "position": 42.1, "duration": 210,
    "canSeek": true, "strategy": "mediaSession+ap+media", "lastPlayingAt": 1731500000000 } }
{ "type": "result", "id": "17", "ok": false, "error": "player_not_found", "state": { … } }
```

Приложение → расширение:

```jsonc
{ "type": "command", "id": "17", "action": "next" }      // next | prev | toggle | play | pause
{ "type": "command", "id": "18", "action": "setVolume", "value": 0.4 }   // 0..1
{ "type": "command", "id": "19", "action": "seek", "value": -10 }        // секунды
```

Мост → расширение: `{ "type": "appStatus", "connected": true|false }`.

Коды ошибок: `no_vk_tab`, `player_not_found`, `no_track`, `no_effect`, `autoplay_blocked`, `volume_unavailable`,
`seek_unavailable`, `tab_disconnected`, `timeout` (+ на стороне приложения `no_browser`).

## Правила честности результата

* Нет подключённых браузеров → `no_browser` сразу, без отправки.
* Браузер сообщил `vkTabs: 0` → `no_vk_tab` сразу.
* Иначе команда отправляется, приложение ждёт `result` не дольше 4 с (`timeout`).
* `page.js` выполняет **первую доступную** стратегию (следующая — только если предыдущая недоступна или
  выбросила исключение, чтобы одно нажатие не переключило два трека) и затем проверяет эффект:
  * next/prev — сменились название/исполнитель/источник или (для «назад») трек начался заново;
  * play/pause — изменилось состояние воспроизведения;
  * громкость — значение плеера стало равно запрошенному (±2 %);
  * перемотка — позиция рядом с целевой.
  Нет эффекта → `no_effect`.

## Выбор вкладки и браузера

Одинаковый приоритет в `background.js` (вкладки) и `PlayerController` (браузеры):
играет → выбран трек → недавно играла → плеер найден → открыт VK → самое свежее обновление.

## Жизненный цикл

* Приложение не запущено → мост раз в 2 с пытается подключиться, кэширует последние `hello`/`state`
  и отдаёт их приложению сразу после подключения.
* Браузер закрыт → stdin моста закрывается → мост завершается → приложение видит разрыв канала.
* Service worker перезапущен → content script переподключается через 1 с; `connectNative` вызывается при
  старте SW, по `onStartup`, по таймеру `chrome.alarms` (1 мин) и с экспоненциальной задержкой после разрыва.
  Открытый порт `connectNative` удерживает SW активным (Chrome 105+).
* Установка/обновление расширения → скрипты внедряются в уже открытые вкладки VK (`chrome.scripting`).

## Перехват клавиш

`LowLevelHookService` (по умолчанию):

* поток с собственным циклом `GetMessage`, `ThreadPriority.Highest`;
* `HotkeyMatcher` решает: строгое совпадение модификаторов; нажатие и соответствующее отпускание
  проглатываются (`return 1`); автоповтор — повтор действия для громкости/перемотки, только глушение для остальных;
* действие уходит в пул потоков, колбэк хука возвращает управление сразу;
* после проглоченной комбинации с Win/Alt (без Ctrl) отправляется «маскирующая» клавиша `0xE8`,
  чтобы отпускание Win не открыло меню «Пуск»;
* сторож раз в 30 с ставит новый хук и снимает старый.

`RegisterHotKeyService` — альтернативный режим: `RegisterHotKey(NULL, …)` в отдельном потоке, `MOD_NOREPEAT`
для неповторяемых действий; ошибки «занято другой программой» показываются в окне.
